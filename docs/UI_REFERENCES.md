# 界面参考与实现说明

本项目先观察公开产品的交互模式，再围绕“需求澄清与人工审阅”重新设计。参考资料只用于理解信息组织和工作流；SpecPilot 的文案、配色、组件、图标和代码均为本项目独立实现，没有复用参考产品的品牌素材或源代码。

## 参考来源

1. **Linear：问题列表与工作区导航**
   [Linear Features](https://linear.app/features) · [Linear Display Options](https://linear.app/docs/display-options) · [Linear Issues](https://linear.app/docs/creating-issues)
   参考点：侧栏组织工作区入口、主区突出当前任务、状态标签与列表视图、让常用动作靠近内容。我们将这些一般交互模式改写成需求档案、草案状态和人工审阅入口。

2. **Vercel v0：自然语言输入与迭代**
   [v0 Quickstart](https://v0.dev/docs/quickstart)
   参考点：以自然语言输入作为开始，并允许用户查看结果、继续调整。SpecPilot 把这一模式用于需求草案，结果需要由开发者编辑确认。

3. **REA：辅助软件界面/行为研究的工具**
   [REA GitHub 项目](https://github.com/morluto/rea)
   项目说明 REA 可协助检查网页、应用和运行时行为，并强调结果需结合证据复核。当前开发会话没有检测到 REA CLI 或 MCP 接入，因此本版界面参考来自上述公开产品页面与文档；没有把 REA 描述成已实际运行。

## 本项目的设计决定

- 用简洁的侧栏和需求档案列表，快速回到最近草案。
- 把自然语言输入放在工作台首屏，让“先写想法”成为主要操作。
- 将结果拆为概览、验收标准、接口草案、测试用例和待确认问题，支持逐项查看。
- 用“AI 草案 / 待人工确认”状态强调验证责任；审阅后的改动保留版本快照。
- 所有实现均使用本项目自建的 CSS、图标和文案，不包含参考产品的 logo、截图或专有视觉素材。
